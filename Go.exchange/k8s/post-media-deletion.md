# 已发布帖子媒体的删除与回收

从 schema 15 对应版本开始，Post Medium／Large 文件每次读取都在主库验证：必须有仍公开、未删除、作者未删除的帖子关联此精确 URL。所有引用都不可公开时返回 404；数据库检查失败时拒绝读取，不回退到对象存储。源站不承诺中断删除提交前已经开始的图片读取。

图片响应使用 `private, no-cache, max-age=0, must-revalidate`。浏览器可以保存图片字节，但再次使用时必须联系源站验证；ETag 的 304 响应也必须先通过帖子资格检查。头像、封面缓存策略不变。部署前形成的一年期 immutable 缓存无法靠新响应头撤销：部署时应清理现有 CDN 图片缓存，并保证代理尊重源站缓存头。已经下载的副本无法撤回。

删帖事务同时写入 `post_media_cleanup`，登记归属经过验证的用户上传目录。登记失败则整个删帖事务回滚。原有 `post-media-gc` 命令同时领取过期上传和已发布媒体删除任务，共用每轮上限、对象超时、claim token、失败退避与租约过期重领机制。所有存活帖子仍引用的对象保留；只有所有删除操作成功，才移除回收任务。回收显式删除该上传的 Medium、Large、三种受支持的 Original 文件名及 manifest，不进行目录或桶的通配删除。

用户上传 UUID 在发布时一次性消费，不能通过发布 API 重新绑定。DevData 路径允许被镜像流程再生成／复用：文件接口同样验证公开资格，但本流程不物理删除 DevData 源对象。回复和引用帖自己的附件也不会因为被引用的原帖删除而被删除。

## 上线依赖

1. 按项目现有部署流程备份并运行 schema 15 迁移。迁移增加精确 URL 查询索引、回收任务表，并一次性登记历史软删除帖的合法用户上传目录；数据库兼容区间为 14–15，新版本要求 15。
2. 由数据库所有者应用 [GC 最小权限示例](post-media-gc-grants.sql.example) 中新增的任务表权限，以及 `post_media`／`posts` 必需列的只读权限。GC 不需要读取用户、帖子正文或获得应用角色成员资格。
3. 部署新版 API 与 `post-media-gc`，清理旧 CDN 图片缓存。保留现有 GC 调度；物理回收延迟受调度频率、积压和重试影响，文件公开资格撤销不依赖 GC 成功。
4. 验收公开图片读取、带旧 ETag 的删帖后读取（应为 404）、共享引用保留、对象删除失败重试和历史任务回收。

此文档描述部署要求，不表示迁移、生产授权或 CDN 清理已执行。
